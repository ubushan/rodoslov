# Журнал разработки: сессия 20.09–02.10.2026

Документ описывает, что и зачем было сделано в проекте «Родослов» за эту сессию:
какие изменения в коде, какие миграции базы, как всё проверялось и что осталось
сделать. Коммиты перечислены в хронологическом порядке, все они в `main`

## Что сделано, по коммитам

  под родителями и по старшинству, у каждой ветви своя полоса.
- Линии связи перерисованы: скобка пары, стояк, шина и отводы со скруглениями.
- Оформление по полу: цвет рамки и заливки, иконки-силуэты вместо фото,

## База данных: миграции

Выполняются в Supabase → SQL Editor.

| Файл | Что делает | Статус |
|---|---|---|
| `supabase/schema.sql` | вся схема: таблицы, RLS, функции доступа, хранилище; в конце — история карточки и древа | выполнен при настройке проекта |
| `supabase/admin.sql` | таблицы `admins` и `platform_settings` | выполнен |
| `supabase/person-history.sql` | `person_changes` и триггер правок карточки | выполнен |
| `supabase/tree-history.sql` | `tree_events` и триггеры истории древа | выполнен |

Две ошибки, найденные при проверке SQL на локальном Postgres и уже исправленные:
1. Триггеры ломали удаление древа: при каскадном удалении людей событие
   ссылалось на уже удалённое древо. Добавлена проверка, что древо ещё есть.
2. `log_tree_event` пропускал постороннего: `if not can_edit_tree(...)`
   не срабатывает, когда функция возвращает `NULL`. Теперь `is not true`.

## Сервер

- Домен `torlmud.ru`, IP `201.24.61.51`, Ubuntu, nginx 1.28, HTTPS от Let's Encrypt.
- Код в `/srv/rodoslov`, служба `rodoslov` (systemd, `npm run start` на 3000),
  nginx проксирует на `127.0.0.1:3000`.
- В `.env.local` на сервере: `NEXT_PUBLIC_SUPABASE_URL`,
  `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `NEXT_PUBLIC_SITE_URL=https://torlmud.ru`,
  `SUPABASE_SERVICE_ROLE_KEY`, `ADMIN_EMAILS`.
- В Supabase: Site URL `https://torlmud.ru`, в Additional Redirect URLs —
  `https://torlmud.ru/auth/callback`; Google-провайдер включён, адрес возврата
  в Google — `https://jlwvdlkadlusjjxpuszt.supabase.co/auth/v1/callback`.

Обновление версии:

```bash
cd /srv/rodoslov && git pull && npm ci && npm run build && sudo systemctl restart rodoslov \
  && sleep 2 && curl -s -o /dev/null -w 'здоровье: %{http_code}\n' http://127.0.0.1:3000/login
```

Грабли, на которые уже наступали:
- `NEXT_PUBLIC_SITE_URL` — только origin, без `/auth/callback`; значение
  вшивается в сборку, поэтому после правки нужен `npm run build`, а не перезапуск.
- Dev-сервер и `next start` нельзя держать в одной папке `.next`: сборка
  затирается и `next start` падает с `routesManifest.dataRoutes is not iterable`.
- Для входа через Google за прокси nginx нужны увеличенные буферы заголовков
  (`proxy_buffer_size 16k; proxy_buffers 8 16k; proxy_busy_buffers_size 32k;`),
  иначе `/auth/callback` отдаёт 502 «upstream sent too big header».

## Как проверялось

- Каждая правка проходит `npx tsc --noEmit` и production-сборку `npm run build`.
- Браузерные наборы на Playwright (WebKit) на тестовом аккаунте: основной
  сценарий древа (`fixes.mjs`), темы (`themes.mjs`), кнопки карточек на телефоне
  (`mobile-buttons.mjs`), свёрнутая панель (`toolbar-mobile.mjs`), шапка
  (`header-mobile.mjs`), меню аккаунта (`account-menu.mjs`), страница истории
  (`tree-history.mjs`), история карточки с откатом (`history.mjs`), экспорт
  в PNG, импорт GEDCOM, фильтр мужской линии (`male-line.mjs`).
- SQL-миграции проверены на локальном Postgres в Docker с заглушками Supabase
  (`auth.users`, `auth.uid()`, `storage.*`, публикация realtime): все четыре
  файла применяются с нуля, 14 видов событий пишутся верно, RLS отдаёт историю
  только участникам, удаление древа проходит целиком.
- Логика отбора мужской линии покрыта юнит-тестом, включая случай, когда
  предок — женщина.
