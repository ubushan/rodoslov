# Родослов

Сервис для совместного составления семейного древа. Родственники заполняют одно древо
вместе: добавляют карточки людей, связывают поколения, загружают фотографии и документы,
а готовое древо скачивают картинкой.

## Технологии

| Слой | Решение |
|---|---|
| Фреймворк | Next.js 15 (App Router, Server Actions, React 19) |
| Язык | TypeScript |
| Стили | Tailwind CSS v4 (токены в `globals.css`) |
| База, авторизация, файлы | Supabase (Postgres + RLS, Auth, Storage, Realtime) |
| Холст древа | React Flow (`@xyflow/react` v12) |
| Раскладка по поколениям | dagre |
| Экспорт в PNG | html-to-image + Canvas |
| Уведомления | sonner |

Шрифты: **Literata** (заголовки) и **Golos Text** (интерфейс) — оба с кириллицей,
подключены через `next/font`.

## Запуск

```bash
npm install
cp .env.example .env.local   # подставьте ключи Supabase
npm run dev
```

### Настройка Supabase

1. Создайте проект на supabase.com.
2. Откройте **SQL Editor** и выполните `supabase/schema.sql` целиком. Скрипт создаёт
   таблицы, RLS-политики, функции доступа, бакеты хранилища и включает Realtime.
3. Скопируйте `Project URL` и `anon public key` из **Project Settings → API** в `.env.local`.
4. Для входа через Google: **Authentication → Providers → Google**, в Redirect URL укажите
   `https://ваш-домен/auth/callback`.
5. На время разработки удобно отключить подтверждение почты:
   **Authentication → Providers → Email → Confirm email**.

## Панель администратора

Панель живёт на `/admin` — она видна только администраторам платформы (остальным страница
отдаёт 404). Внутри: сводка по платформе, список пользователей с блокировкой и удалением,
все древа с составом участников и приглашениями, настройки регистрации и пределов.

Чтобы её включить:

1. Выполните в **SQL Editor** файл `supabase/admin.sql` — он создаёт таблицы `admins`
   и `platform_settings`.
2. Добавьте в `.env.local` ключ `SUPABASE_SERVICE_ROLE_KEY` (Project Settings → API →
   `service_role`). Он читается только на сервере и в браузер не попадает.
3. Впишите свою почту в `ADMIN_EMAILS` — это запасной вход в панель, он работает даже
   без таблицы `admins`. Дальше права администратора можно выдавать на вкладке
   «Пользователи», они сохранятся в базе.

Настройки платформы, которые сейчас действуют: открытая регистрация и предел числа людей
в одном древе (0 — без предела). Обе проверки выполняются на сервере — в регистрации
и в добавлении карточки.

## Модель данных

```
profiles           профиль пользователя (создаётся триггером при регистрации)
trees              древо
tree_members       участник древа + роль: owner | editor | viewer
tree_invites       ссылка-приглашение: токен, роль, срок, лимит переходов
persons            карточка человека
relationships      связь: parent (from = родитель, to = ребёнок) или spouse
person_attachments архив: сканы документов и дополнительные фотографии
admins             администраторы платформы (файл supabase/admin.sql)
platform_settings  настройки платформы: ключ — значение (файл supabase/admin.sql)
```

Доступ полностью закрыт Row Level Security. Проверки вынесены в `security definer`-функции
`is_tree_member`, `can_edit_tree`, `is_tree_owner` — иначе политика на `tree_members`
зациклилась бы сама на себе.

Права ролей:

| Действие | Владелец | Редактор | Зритель |
|---|:--:|:--:|:--:|
| Смотреть древо и скачивать картинку | ✔ | ✔ | ✔ |
| Добавлять и менять карточки, связи, файлы | ✔ | ✔ | — |
| Приглашать и исключать участников | ✔ | — | — |
| Переименовать и удалить древо | ✔ | — | — |

## Как работает совместное редактирование

Мутации идут через Server Actions, которые пишут в Postgres под сессией пользователя —
RLS проверяет роль на стороне базы, а не в интерфейсе. Холст подписан на Realtime-канал
`tree:{id}`: изменения в `persons` и `relationships` вызывают `router.refresh()`, и правки
родственников появляются без перезагрузки страницы.

## Экспорт картинки

`getNodesBounds` считает габариты всего древа, `getViewportForBounds` подбирает масштаб,
`html-to-image` снимает слой `.react-flow__viewport` с двойным разрешением. Затем на Canvas
дорисовывается подпись с названием древа и датой. Служебные элементы (точки связей,
сетка, миникарта) прячет класс `.exporting`.
